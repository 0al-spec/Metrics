## ❌ Files to IGNORE (Temporary/Generated)

### Python Artifacts (Auto-generated)
- `__pycache__/` - Python bytecode cache
- `*.pyc`, `*.pyo`, `*.pyd` - Compiled Python
- `*.egg-info/` - Package metadata
- `venv/`, `env/` - Virtual environments

### Extractor Outputs (Generated by script)
- `sib_metrics.json` - Default output

- `task_metrics/` - Custom output directory
- `metrics_output/` - Custom output directory

- `SIB/*.fdb_latexmk`, `*.fls` - Latexmk files

### Logs & Temporary Files

## 📝 Commit Workflow

### First Time Setup (Add new files)
```bash
# Add all extractor source files
git add extract_metrics.py test_output_modes.py
git add requirements-extractor.txt example_spec.md

# Add all documentation
git add *.md

# Add updated .gitignore
git add .gitignore

# Commit
git commit -m "Add SIB metrics extractor with flexible output modes"
```

### Regular Updates
```bash
# Check what's changed
git status

# Add specific files
git add extract_metrics.py EXTRACTOR_README.md

# Or add all tracked files
git add -u

# Commit with descriptive message
git commit -m "Update extractor with JSON mode improvements"
```

### Verify No Temp Files
```bash
# Check ignored files aren't being added
git status --ignored

# Should NOT see any *.json outputs or __pycache__
```

## 🧹 Clean Up (if needed)

### Remove accidentally committed temp files
```bash
# Remove from git but keep locally
git rm --cached task_b1.json
git rm --cached "*.log"

# Commit the removal
git commit -m "Remove temporary files from tracking"
```

### Clean all temp files
```bash
# Remove Python cache
find . -type d -name __pycache__ -exec rm -rf {} + 2>/dev/null

# Remove JSON outputs
rm -f *_metrics.json *.json 2>/dev/null

# Remove LaTeX artifacts
cd SIB && make clean
```

## 📊 Extractor Output Strategy

### For Development/Testing
**Don't commit extraction results** - they're temporary and machine-specific.

```bash
# Run extractions
python extract_metrics.py specs/ -o results.json

# Results are automatically ignored
# No need to clean up before commit
```

### For Long-term Tracking (optional)
If you want to track metrics over time:

1. **Create a separate branch:**
   ```bash
   git checkout -b metrics-tracking
   ```

2. **Commit specific metrics:**
   ```bash
   git add specs/*_metrics.json
   git commit -m "Metrics snapshot: 2026-01-26"
   ```

3. **Keep main branch clean:**
   ```bash
   git checkout main
   # Continue development
   ```

## 🎯 Best Practices

1. **Never commit:**
   - `__pycache__/` or `*.pyc` files
   - `*_metrics.json` outputs (unless tracking intentionally)
   - Virtual environments (`venv/`)
   - IDE settings (`.vscode/`, `.idea/`)

2. **Always commit:**
   - Source code (`*.py`)
   - Documentation (`*.md`)
   - Configuration (`requirements.txt`, `.gitignore`)
   - Tests (`test_*.py`)

3. **Review before commit:**
   ```bash
   git diff --staged
   ```

4. **Keep commits atomic:**
   - One feature per commit
   - Clear commit messages
   - Related files grouped together

## 🔍 Troubleshooting

### "I accidentally committed a temp file"
```bash
git rm --cached file.json
git commit -m "Remove temp file from tracking"
```

### ".gitignore not working"
If files are already tracked, .gitignore won't affect them:
```bash
# Remove from tracking
git rm --cached file.json

# Now .gitignore will work
```

### "Check if file is ignored"
```bash
git check-ignore -v file.json
```

### "See all ignored files"
```bash
git status --ignored
```
